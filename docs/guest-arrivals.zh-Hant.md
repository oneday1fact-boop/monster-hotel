# 1.26：在旅館迎接新朋友，再開放後續關卡

## 已實作流程

1. 完成「怪物大合照」後，關卡地圖出現「先到我的旅館迎接小雷（小雲）」提示及可直接前往的按鈕。小雷到旅館接待處等候，仍未計入正式住客。
2. 在旅館點「入住突發事件」開始原本的暴雨風鈴迷宮。成功帶小雷入大廳才確認入住、保存完成紀錄及首次500金幣。旅館、封面及大廳同步加入小雷。
3. 接住兩個新普通挑戰：「小雷的風信快遞」7×7滑行迷宮，收齊四把風匙後到出口，最少18次有效移動；「雨後的雙色虹燈」共用鏡片雙光路，最少10次轉鏡。兩關使用經解題器驗證的固定配置及成熟的委託操作元件，並非新種類玩法；故事、完成紀錄、草稿及一次性500金幣獨立保存，不影響重複委託的次數或草稿。復原、重做與提示免費。
4. 完成上述兩關後才出現蜜寶入住提示。去旅館接待處迎接蜜寶，完成連動咕咕鐘事件後正式入住，再開放蜜罐、影子下午茶及枕頭彈彈關卡。
5. 原「神秘客的午夜行李箱」延後至兩位住客及上述蜜寶三關完成後，讓新玩家一次只有一個清楚的新事件。1.25 已經開始／完成的午夜行李箱保留原草稿及已領獎，不回收獎勵或重置。

兩次入住事件沿用原 `storm-arrival`、`clockwork-guest` 完成 ID，不再只是從普通關卡直接開始的獨立故事。未完成的入住從地圖轉往旅館；完成後可在地圖重玩，但不再派首次獎勵。小熊沿用原創黃色蜜寶造型及名字。

## 存檔與操作

新 `cloudTasks` 只保存兩關的獨立解題草稿。讀檔驗證配置序號與合法棋盤，保留所有既有金幣、房產、裝飾、住客、照片、委託與完成 ID。新玩家按主線順序逐步解鎖；舊玩家已完成的關卡可照常重玩。入住確認及新關派獎均先成功存檔才顯示成功，失敗不解鎖或派獎。

入住後返回旅館能即時看見新朋友；中途離開可繼續原事件。語言、靜態偏好及設定沿用現有系統。所有版面固定一頁，關卡地圖用上一頁／下一頁。

`npm test` 驗證事件先後、關卡閘門、配置可解與獎勵只派一次；`npm run build` 建置。`npm run review:record` 用 production preview 錄一次真實的兩次入住及中間兩關操作，輸出 H.264 MP4 和 GIF。錄影只預放入住前的舊關完成紀錄及5000金幣，之後四次完成皆實際操作，結尾7000金幣；沒有注入新關完成資料。
