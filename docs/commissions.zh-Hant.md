# 1.24：可重複賺金幣的旅館委託

## 玩家入口與循環

「我的旅館」右下新增金幣圖案的「委託賺幣」。待解鎖新翼房間的詳情亦可直接前往委託，返回後保留房產與餘額。原故事關卡、偵探案與永久住客解鎖不改；委託的客串角色不會自動加入封面或酒店永久住客。

流程是：選難度 → 接一張委託 → 解題 → 交付收幣 → 接下一張不同配置，或回旅館儲錢擴建。沒有入場費、冷卻、日曆要求、體力、真實廣告或付費提示。每個類別／難度獨立保存未完成草稿，離開可續玩。

## 三類進階玩法

| 委託 | 玩法與難度 | 表現 |
|---|---|---|
| 巡夜迷宮 | 滑到牆才停，沿途收齊 3／4／5 把鑰匙再到出口；棋盤 6×6、7×7、8×7 | 角色沿實際每格路徑連續滑行，鑰匙收集與出口發光 |
| 幽靈布草急件 | 6×6，11–13 件固定軸向布草車；星星被單到右邊出口；不是舊 5×4 的原答案 | 可直接拖動，放手才落位；觸控取消不落位，選取、投影、滑行與吸附有回饋 |
| 雙色星燈 | 兩道不同顏色的光共用 8／10／12 片鏡子，各自照齊水晶，再到同色出口 | 連續流動光點、柔光光束、鏡片旋轉、水晶點亮與原有分層角色待機 |

方向控制是十字排列；可免費復原、重做、重置與提示。提示從當前狀態求解，不是假定玩家一直跟初始答案。沒有計時或一步走錯就作廢的懲罰。

## 配置驗證與輪替

每個類別的每個難度有 8 款不同基礎配置，共 **72 款**。完成後按該類別／難度的序號輪替，之後亦交替使用左右／上下鏡像（布草只上下反射，以保留右側出口）。鏡像是重玩變化，不冒稱成全新的劇情關卡；有限基礎配置不代表無限獨立設計。

`generate-commissions.py` 使用固定 seed 1242026 離線編製 `commissionData.ts`，出貨時沒有臨場隨機生成無解棋盤：

- 迷宮滑行停點形成可互達的區域，最短解不少於 12／16／20 次滑行。
- 布草從可解的狀態圖反向選取難度，最短解不少於 16／22／28 次單格移動。拖一次跨多格時，操作計數算一次拖動，不把它與上述單格下限混為一談。
- 雙色鏡子每款完整配置恰有一解，兩條正確光路至少共用兩片鏡子；只點亮其中一色不算完成。

單元測試另用遊戲實際 TypeScript 解題器重驗 72 款的可解性、最短步數、鏡像與鏡子唯一解，並非只信任產生器寫下的答案。

## 金幣與擴建價格

| 難度 | 每張成功交付 |
|---|---:|
| 進階 | 320 |
| 挑戰 | 480 |
| 專家 | 720 |

| 新翼房間 | 新價格 | 前置房間 |
|---|---:|---|
| 樹屋書室 | 4,800 | 無 |
| 星空觀測室 | 7,200 | 無 |
| 月影音樂室 | 10,800 | 樹屋書室 |
| 蜜糖烘焙房 | 15,600 | 星空觀測室 |

總價 38,400；由零開始儲第一間書室需 15 張進階、10 張挑戰或 7 張專家委託。主線既有金幣亦可使用。這是本版試玩平衡，不是假稱已經實際玩家長期測試過的最終經濟。

已買的房間永久保留，不補收差額、不回收現有金幣。裝飾與場景價格不改。高難度不扣減重試玩家的基本獎勵。

## 保存與派獎安全

原存檔新增可選 `commissions` 欄位，保存每個類別／難度的已完成序號與草稿、復原／重做紀錄。沒有這欄的舊存檔直接開始委託，不重置其他欄位。

每次操作先寫成功才更新畫面。交付時驗證當前序號及實際棋盤完成狀態，原子地增加金幣、遞增序號、移除已領草稿；雙擊、重入或舊序號不能再領。同一種類下一張可以再賺錢，但必須重新解未完成配置。儲存失敗不顯示派獎或收幣動畫；不接受金幣整數溢位。

## 本版驗證結果

203 個單元測試（30 個檔案）通過；29 個不同的相關瀏覽器測試通過，包括 15 個委託測試、9 個全景／房產測試、4 個原旅館動態／裝飾測試及 1 個原四房新翼購買測試。覆蓋四種手機尺寸的中英文、真實觸控拖動／取消、重複派獎防護、儲存失敗、設定面板、續玩與賺幣買房。

TypeScript／Vite build、Android assembleDebug 與 bundleRelease 成功；最終 APK 為 1.24／25、target SDK 36，debug 簽章有效，47 個 production 資產逐檔相同。release AAB 只是未簽署編譯檢查檔，沒有上載 Play。91 秒 H.264／yuv420p 實玩片及 60 幀的拖動 GIF 已驗證；不代表已做真機幀率測試。
